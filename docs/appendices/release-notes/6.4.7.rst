.. NOTE::

    In development. 6.4.7 isn't released yet. These are the release notes for
    the upcoming release.

.. NOTE::

    If you are upgrading a cluster, you must be running CrateDB 5.0.0 or higher
    before you upgrade to 6.4.7.

    We recommend that you upgrade to the latest 6.3 release before moving to
    6.4.7.

    A rolling upgrade from >= 6.3.0 to 6.4.7 is supported.
    Before upgrading, you should `back up your data`_.

.. WARNING::

    Tables that were created before CrateDB 5.x will not function with 6.x
    and must be recreated before moving to 6.x.x.

    You can recreate tables using ``COPY TO`` and ``COPY FROM`` or by
    `inserting the data into a new table`_.

.. _back up your data: https://cratedb.com/docs/crate/reference/en/latest/admin/snapshots.html
.. _inserting the data into a new table: https://cratedb.com/docs/crate/reference/en/latest/admin/system-information.html#tables-need-to-be-recreated

Fixes
=====

- Fixed an issue where a logical replication subscription's active connection
  could be unexpectedly closed when an earlier connection attempt for a
  subscription with the same name failed afterwards. As a consequence, both
  data replication and metadata tracking could stop for the affected
  subscription.

- Fixed an issue where logical replication metadata tracking could stop after a
  subscriber restart if the connection to the publisher was not ready. As a
  consequence, schema changes and new partitions could fail to replicate,
  while data replication on existing partitions could continue.

- Fixed an issue where data replication on existing partitions could stall
  after a publisher restart when using
  :ref:`pg_tunnel mode <sql-create-subscription-conn-info>` for logical
  replication.
