.. NOTE::

    In development. 6.5.3 isn't released yet. These are the release notes for
    the upcoming release.

.. NOTE::

    If you are upgrading a cluster, you must be running CrateDB 5.0.0 or higher
    before you upgrade to 6.5.3.

    We recommend that you upgrade to the latest 6.4 release before moving to
    6.5.3.

    A rolling upgrade from >= 6.4.0 to 6.5.3 is supported.
    Before upgrading, you should `back up your data`_.

.. WARNING::

    Tables that were created before CrateDB 5.x will not function with 6.x
    and must be recreated before moving to 6.x.x.

    You can recreate tables using ``COPY TO`` and ``COPY FROM`` or by
    `inserting the data into a new table`_.

.. _back up your data: https://cratedb.com/docs/crate/reference/en/latest/admin/snapshots.html
.. _inserting the data into a new table: https://cratedb.com/docs/crate/reference/en/latest/admin/system-information.html#tables-need-to-be-recreated

Fixes
=====

- Fixed an issue where a comparison on object columns could lead to a wrong
  result if the objects had the same amount of keys and some values were
  ``null``.

- Fixed an issue that caused queries on sub-columns of ignored objects to match
  no rows.

- Fixed an issue that caused ``generate_series`` to round up milliseconds to
  seconds.

- Fixed an issue that caused the milliseconds part in the interval step in
  ``generate_series`` to be multiplied by 10.

- Fixed an issue where ``KILL <job id>`` could not stop a ``generate_series``
  call.

- Fixed an issue that caused ``generate_series`` to return no rows, or to never
  finish, if the series had more than ``2147483647`` values or if the step value
  pointed away from the stop value, or if the stop value is the maximum value
  for the given type.

- Fixed an issue that incorrectly allowed dropping subscribed tables by
  ``DROP SCHEMA CASCADE``.
