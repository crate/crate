.. NOTE::

    In development. 6.5.2 isn't released yet. These are the release notes for
    the upcoming release.

.. NOTE::

    If you are upgrading a cluster, you must be running CrateDB 5.0.0 or higher
    before you upgrade to 6.5.2.

    We recommend that you upgrade to the latest 6.4 release before moving to
    6.5.2.

    A rolling upgrade from >= 6.4.0 to 6.5.2 is supported.
    Before upgrading, you should `back up your data`_.

.. WARNING::

    Tables that were created before CrateDB 5.x will not function with 6.x
    and must be recreated before moving to 6.x.x.

    You can recreate tables using ``COPY TO`` and ``COPY FROM`` or by
    `inserting the data into a new table`_.

.. _back up your data: https://cratedb.com/docs/crate/reference/en/latest/admin/snapshots.html
.. _inserting the data into a new table: https://cratedb.com/docs/crate/reference/en/latest/admin/system-information.html#tables-need-to-be-recreated

Fixes
=====

- Fixed an issue in the PostgreSQL wire protocol implementation that could cause
  clients to not receive an error message if:

    - The client sent a parse, bind and execute for either an ``insert``,
      ``update`` or ``delete`` statement.
    - The client send another message resulting in an error. For example sending
      a value that doesn't match the statement's type.
    - The client didn't follow up with a ``sync`` message.

- Fixed an issue where querying ``sys.nodes`` might return ``SQLParseException[Values less than -1 bytes
  are not supported: -86016b]``.

- `Yannic Hamann <https://github.com/yannic-hamann-abb>`_ fixed an issue that
  caused :ref:`ANALYZE <analyze>` to exceed the configured I/O rate limit
  during statistics collection.

- Fixed an issue that could cause Logical Replication to fail with an error
  ``java.lang.IllegalStateException: source not found for seqno=...`` after
  primary shards on the subscriber cluster were relocated and segments of the
  published table were merged on the publisher cluster, for example by running
  ``OPTIMIZE``.

- Fixed an issue that could discard recently replicated data from the
  subscriber cluster when dropping a subscription shortly after shard recovery.

- Fixed an issue that could prevent Logical Replication from resuming after
  subscriber node restarts, shard recovery, or replica promotion.

- Fixed an issue causing ``RESTORE SNAPSHOT`` to silently restore only one
  of several tables if the rename options ``schema_rename_replacement``
  or ``table_rename_replacement`` mapped them to the same name.
  Now it fails with an error, similar to clashes with an existing table.

- Fixed an issue that could cause :ref:`JWT authentication <auth_jwt>` to
  hang if the issuer accepted the connection but never responded, when fetching
  the OpenID configuration or its keys. These requests now time out after
  ``5 seconds``.

- Fixed an issue that caused an error with the message
  ``Couldn't find x in SourceSymbols`` in certain queries with aliased columns
  and with the ``optimizer_rewrite_to_query_then_fetch`` enabled.

- Fixed an issue where statistics gathering on foreign tables would abort and
  raise a ``PSQLException[FATAL: role "crate" does not exist]`` if
  there was no mapping of the ``crate`` superuser to the foreign server pointing
  to a remote user with read access on the foreign table. Also improved documentation
  on this required mapping. See :ref:`administration-fdw-statistics`.

- Fixed an issue that caused queries using the
  :ref:`hyperloglog_distinct <aggregation-hyperloglog-distinct>` aggregation to
  fail with ``EOFException`` during a rolling upgrade from :ref:`version_6.1.0`
  to :ref:`version_6.2.0`.
